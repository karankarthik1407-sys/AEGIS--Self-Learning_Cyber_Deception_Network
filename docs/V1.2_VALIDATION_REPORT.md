## Trust claims validated at this checkpoint

- A browser request cannot choose its AEGIS role through a header.
- A viewer cannot mutate; an analyst cannot invoke administrator routes.
- A present invalid license does not silently become Research Edition.
- License recovery remains possible only through an administrator-scoped route.
- A command does not enter its route unless the preflight audit append succeeds.
- The request body and raw desktop token are not stored in operator audit rows.
- An existing audit chain does not silently restart after key loss.
- Ordinary SQL update/delete paths cannot rewrite operator history.
- Licensing and role logic do not modify Safety Kernel invariants.

## Claims not validated

This checkpoint does not establish:

- Windows 10/11 installation, upgrade, reboot or crash-recovery behavior;
- Authenticode trust or installer signing;
- enterprise IAM, named-user identity, session revocation or multi-tenancy;
- an embedded vendor public-key root, license revocation or tamper-proof DRM;
- TPM/HSM custody, trusted time, non-repudiation or WORM audit storage;
- resistance to a local administrator who can replace the executable;
- live-enterprise detection accuracy or criminal/person attribution;
- real packet enforcement, external pursuit or hack-back; or
- patent novelty, validity, freedom to operate or filing readiness.

## Required Windows acceptance procedure

On an isolated 64-bit Windows 10/11 machine:

1. extract the v1.2 source archive;
2. double-click `BUILD_AEGIS_EXE.bat`;
3. confirm all 88 tests pass inside the isolated build environment;
4. confirm both PyInstaller builds complete;
5. confirm the frozen `AEGIS.exe --headless-check` passes;
6. compare the produced ZIP with its SHA-256 file;
7. install using `Install-AEGIS-Desktop.ps1` under UAC;
8. verify Program Files and ProgramData ACLs, including the license/public-key
   pair and generated audit key;
9. verify the service is delayed-auto-start and survives desktop closure;
10. confirm the Access & Audit workspace shows the intended role/license state;
11. execute one permitted, one role-denied and one invalid-license command and
    verify the audit chain;
12. test clean reboot, service restart, deliberate process crash and recovery;
13. test upgrade, repair and data-preserving uninstall; and
14. repeat after Authenticode signing and independent security review.

Only after this procedure may a specific Windows package be described as built
and acceptance-tested. Even then, enterprise pilot use requires the production
gates in `DESKTOP_PRODUCT_GUIDE.md` and `ACCESS_AUDIT_GUIDE.md`.
